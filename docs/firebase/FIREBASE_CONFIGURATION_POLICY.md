# Firebase client configuration policy

## Files generated per developer project

The following files are generated by FlutterFire CLI / Firebase Console and must remain local to each developer's Firebase project:

- `lib/firebase_options.dart`
- `android/app/google-services.json`
- `ios/Runner/GoogleService-Info.plist`
- `.firebaserc`

The native files and generated Dart file contain Firebase client configuration. These values are not service-account credentials, but they identify an environment and should not make an external clone silently target the maintainer's production project.

## Firebase CLI configuration

The Firebase CLI file `firebase.json` is developer-local and ignored by Git.

For a new checkout, create it from the portable template:

```bash
cp firebase.json.example firebase.json
```

The example includes Functions and Hosting configuration only. It deliberately omits a top-level Firestore deployment section because the current root rules file is not deployment-ready. Do not add or deploy Firestore Rules until the ruleset has been restructured, independently reviewed and approved.

The Emulator QA scripts create isolated temporary Firebase configurations; they do not need the repository's local `firebase.json`.

FlutterFire may add project-specific platform mappings to the local `firebase.json` during `flutterfire configure`. Keep those mappings out of commits.

## Setup after cloning

1. Create or select a Firebase project you own. Use synthetic data for development.
2. Register the Android application using the project's actual `applicationId` and register the iOS app using the Xcode bundle identifier.
3. Enable the Authentication providers required by the app and create a development Firestore database.
4. Install FlutterFire CLI and run:

   ```bash
   dart pub global activate flutterfire_cli
   flutterfire configure --project YOUR_FIREBASE_PROJECT_ID --platforms android,ios,web
   ```

5. Verify the generated files above are local and ignored by Git.
6. Set the Firebase CLI project alias locally with `firebase use --add`.
7. Do not deploy Rules or Functions to the maintainer's project. Use your own development project and review the Rules size/security blockers documented in `INDEPENDENT_FIREBASE_SETUP.md`.

## CI behaviour

GitHub Actions copies `lib/firebase_options.dart.example` to the ignored `lib/firebase_options.dart` path. The example contains nonfunctional placeholder values solely so analysis and compilation can resolve the imported symbols. It is not a Firebase project configuration and must never be used to run the app against a real backend.

## History handling

Removing these files from the current Git index does not remove the existing blobs from previous commits. The audited history currently contains client configuration, not detected service-account/private-key patterns. Client API keys are not server secrets. History rewriting is not recommended for this cleanup because no true secret was found by the available scanner; if a true credential is later identified, revoke/rotate it first and then separately assess history rewriting.
